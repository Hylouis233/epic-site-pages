# Security Policy

Do not open a public issue for credentials, private endpoints, source-system access details, or a vulnerability that could expose sensitive data.

Use GitHub’s private vulnerability-reporting feature when available. Include the affected path, reproduction steps, impact, and a minimal proof of concept. Do not access, alter, or retain data beyond what is necessary to demonstrate the issue.

Public data corrections and methodological concerns are not security vulnerabilities; use the data-correction issue template instead.
